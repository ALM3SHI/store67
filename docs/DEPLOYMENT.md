# النشر وربط الخدمات

## 1) قاعدة البيانات (Supabase أو أي PostgreSQL)
1. أنشئ مشروع Supabase (المنطقة الأقرب: Middle East / Bahrain إن توفرت، أو Frankfurt).
2. من Project Settings → Database انسخ **Connection string** (Session pooler) وضعه في `DATABASE_URL`.
3. من جهازك: `DATABASE_URL="..." npm run db:migrate` ثم `npm run db:seed`.
4. أنشئ حساب المالك: `DATABASE_URL="..." ADMIN_PASSWORD='...' npm run admin:create -- you@domain.sa "الاسم" owner`.
5. الترحيلات تفعّل RLS على كل الجداول؛ لا تضف سياسات تسمح للمتصفح بقراءة الجداول.

**النسخ الاحتياطي:** Supabase يأخذ نسخًا يومية في الخطط المدفوعة. نسخة يدوية:
```bash
pg_dump "$DATABASE_URL" --no-owner --format=custom -f store76-$(date +%F).dump
# استعادة إلى قاعدة فارغة:
pg_restore --no-owner -d "$NEW_DATABASE_URL" store76-YYYY-MM-DD.dump
```
احفظ النسخ خارج المزوّد نفسه، وجرّب الاستعادة مرة واحدة على الأقل قبل الإطلاق.

## 2) تخزين الملفات
على Vercel لا يوجد قرص دائم، لذا:
1. في Supabase → Storage أنشئ دلوين: `public-media` (Public) و`private-docs` (**Private**).
2. اضبط `STORAGE_DRIVER=supabase` و`SUPABASE_URL` و`SUPABASE_SERVICE_ROLE_KEY` (مفتاح خادم فقط).

## 3) الاستضافة على Vercel
1. ارفع المشروع إلى مستودع Git خاص (الملفات الحساسة مستبعدة في `.gitignore`).
2. Import في Vercel → Framework: Next.js.
3. أضف متغيرات البيئة من `.env.example` (Production):
   `APP_ENV=production`، `APP_URL=https://your-domain.sa`، `SESSION_SECRET` (32+ حرفًا عشوائيًا)، `DATABASE_URL`، `CRON_SECRET`، ومفاتيح التخزين والدفع والشحن.
   **لا تضف** `PAYMENTS_TEST_GATEWAY` في الإنتاج.
4. `vercel.json` يجدول `/api/cron/expire-orders` كل 15 دقيقة لإعادة مخزون الطلبات غير المدفوعة. (خطة Hobby تسمح بتشغيل يومي فقط؛ اللوحة تشغّل نفس التنظيف عند فتحها، وإتمام كل طلب يشغّله أيضًا.)
5. أي بيئة Preview: `APP_ENV=staging` (لا فهرسة، وبوابة الاختبار متاحة إن أردت).

بديل Vercel: أي خادم Node 20+ (`npm ci && npm run build && npm start`) خلف HTTPS.

## 4) النطاق
1. Vercel → Settings → Domains → أضف `your-domain.sa` و`www`.
2. عدّل سجلات DNS لدى مسجّل النطاق كما يطلب Vercel (A أو CNAME).
3. حدّث `APP_URL` لنفس النطاق ثم أعد النشر (روابط الطلبات وخريطة الموقع تعتمد عليه).

## 5) Moyasar (الدفع)
1. افتح حساب تاجر لدى Moyasar وأكمل التوثيق (سجل تجاري، حساب بنكي...). مدى وApple Pay وSTC Pay تُفعَّل من جهتهم حسب حسابك.
2. ابدأ بمفاتيح **الاختبار**: `MOYASAR_SECRET_KEY=sk_test_...`.
3. Dashboard → Settings → Webhooks: أضف
   - URL: `https://your-domain.sa/api/payments/moyasar/webhook`
   - Secret Token: قيمة عشوائية طويلة، وضعها في `MOYASAR_WEBHOOK_SECRET`
   - Events: payment_paid, payment_failed, payment_refunded, payment_voided
4. جرّب طلبًا ببطاقات الاختبار من توثيق Moyasar: نجاح، رفض، إلغاء، ثم استرجاع من لوحة التحكم. تأكد أن حالة الطلب تتغير وأن «التحقق من حالة الدفع لدى البوابة» يعمل.
5. في الإعدادات → طرق الدفع اختر شعارات الطرق المفعلة فعلًا في حسابك.
6. بعد اعتماد الحساب الحي: بدّل إلى `sk_live_...` وأنشئ Webhook حيًا بنفس الطريقة، ثم نفّذ عملية حقيقية صغيرة واسترجعها.

> راجع توثيق Moyasar الرسمي قبل الإطلاق (https://docs.moyasar.com) — التكامل يستخدم Invoices API والمصادقة Basic بالمفتاح السري، وأي تغيير من جهتهم يتطلب تحديث `services/payments/moyasar.ts`.

## 6) أرامكس (الشحن)
1. اطلب من مدير حسابك في أرامكس بيانات API: UserName, Password, AccountNumber, AccountPin, AccountEntity، وعنوان بيئة الاختبار.
2. ضعها في متغيرات `ARAMEX_*` واضبط `ARAMEX_BASE_URL` لبيئة الاختبار أولًا.
3. في الإعدادات → الشحن: أدخل عنوان المستودع وهاتفه، واختر «حساب مباشر من أرامكس» إن أردت تسعيرًا حيًا.
4. اختبر: طلب تجريبي ← «إنشاء شحنة أرامكس» من صفحة الطلب ← تأكد من رقم التتبع وملصق الشحن ← «تحديث التتبع».
5. أنواع المنتج المستخدمة: `DOM/ONP` (محلي). إن كان عقدك بنوع آخر عدّلها في `services/shipping/aramex.ts`.
6. بدون بيانات أرامكس: الشحن يدوي بسعر ثابت، وتدخل رقم التتبع ورابطه يدويًا من صفحة الطلب.

## 7) Google
- **Search Console:** أضف النطاق كـ Domain property (سجل TXT) أو انسخ قيمة وسم HTML إلى الإعدادات → محركات البحث. ثم أرسل `https://your-domain.sa/sitemap.xml`.
- **Merchant Center:** بعد اكتمال صفحات السياسات وبيانات التواصل، أضف خلاصة: `https://your-domain.sa/feeds/google-merchant.xml` (جدولة يومية). أدخل GTIN في المنتج إن وُجد.
- **Analytics:** أدخل معرّف GA4 في الإعدادات → أدوات القياس. لا يُحمّل إلا بعد موافقة الزائر.
- لا توجد طريقة تقنية تضمن ترتيبًا معينًا في نتائج البحث؛ المتجر يزيل العوائق التقنية فقط.

## 8) الذكاء الاصطناعي — Gemini (اختياري)
1. افتح https://aistudio.google.com/apikey بحساب Google وأنشئ مفتاح API.
2. ضعه في `GEMINI_API_KEY`. النموذج الافتراضي `gemini-3.8-flash`؛ لاستخدام `gemini-3.7-flash` اضبط `GEMINI_MODEL=gemini-3.7-flash` (جوجل تحوّل طلباته حاليًا إلى 3.8 تلقائيًا).
3. ما يتفعّل:
   - **مساعد الدعم في المتجر:** يجيب من بيانات المتجر فقط (المنتجات، الشحن، الدفع، السياسات)، يرشّح المنتج المناسب مع زر للانتقال إليه، ويتذكر سياق المحادثة. ويعرض **حالة الطلب** إذا أعطاه العميل رقم الطلب ورقم الجوال معًا (نفس تحقق صفحة التتبع، بدون عنوان أو بيانات شخصية).
   - **الكاتب الذكي في لوحة التحكم:** في صفحة المنتج اكتب ملاحظاتك عن المنتج فيكتب مسودة العنوان والوصف والمزايا والأسئلة بالعربي والإنجليزي، لتراجعها ثم تطبّقها. لا يكتب مواصفات فنية.
4. التكلفة: يُحتسب كل سؤال على حسابك في Google. `ASSISTANT_DAILY_LIMIT` (افتراضي 300) يحدد أقصى عدد أسئلة يوميًا، وبعده يعود المساعد للأسئلة المتكررة تلقائيًا. وحد لكل زائر 30 سؤالًا في الساعة.
5. بدون مفتاح: يعمل المساعد من الأسئلة المتكررة، وتبقى ميزة حالة الطلب تعمل.
6. بديل: `ANTHROPIC_API_KEY` لاستخدام Claude بدل Gemini.

## 9) بريد العملاء (Resend)
يُرسل للعميل — إن أدخل بريده عند الطلب — رسالة عند: تأكيد الطلب (مدفوع أو دفع عند الاستلام)، الشحن (مع رقم التتبع)، التسليم، والإلغاء. كل رسالة تحمل رابط صفحة الطلب الخاص به.
1. افتح حسابًا على https://resend.com (الخطة المجانية تكفي للبداية).
2. Domains → Add domain → أضف نطاقك (يفضّل نطاقًا فرعيًا مثل `mail.your-domain.sa`) وأضف سجلات DNS التي يطلبها (SPF و DKIM) لدى مسجّل النطاق، وانتظر حالة Verified.
3. API Keys → أنشئ مفتاحًا بصلاحية Sending فقط.
4. متغيرات البيئة: `RESEND_API_KEY=re_...`، `EMAIL_FROM="STORE 76 <orders@mail.your-domain.sa>"`، واختياريًا `EMAIL_REPLY_TO=support@your-domain.sa` لتصل ردود العملاء لبريدك.
5. لوحة التحكم → الإعدادات → الإشعارات والتنبيهات: أضف بريد الفريق ثم «إرسال تنبيه تجريبي».
6. كل رسالة تظهر في صفحة الطلب (قسم «الرسائل المرسلة») بحالتها، ويمكن إعادة إرسالها من هناك.

بدون هذه المتغيرات لا يُرسل شيء؛ في بيئة التطوير تُطبع الرسائل (ومنها رابط استعادة كلمة المرور) في نافذة الخادم.

## 10) تنبيهات تيليجرام (طلب جديد + أخطاء)
1. في تيليجرام افتح @BotFather → `/newbot` → اختر اسمًا، وانسخ الـ token إلى `TELEGRAM_BOT_TOKEN`.
2. أرسل أي رسالة لبوتك الجديد (أو أضفه لمجموعة الفريق وأرسل رسالة فيها).
3. افتح في المتصفح `https://api.telegram.org/bot<TOKEN>/getUpdates` وانسخ قيمة `chat.id` إلى `TELEGRAM_CHAT_ID` (للمجموعات تبدأ بـ `-`).
4. أعد النشر، ثم «إرسال تنبيه تجريبي» من الإعدادات.

يصلك تنبيه بكل طلب مؤكد، وتنبيه عند أول ظهور لأي خطأ في الخادم (ثم مرة كل ساعة على الأكثر إن تكرر). تفاصيل الأخطاء في لوحة التحكم → سجل الأخطاء.

## 11) مراقبة توفّر الموقع
`/api/health` يرجع 200 عندما يعمل الموقع وقاعدة البيانات. أضفه في خدمة مراقبة مجانية مثل UptimeRobot أو Better Stack (فحص كل 5 دقائق) لتصلك رسالة إن توقف الموقع كليًا — وهي حالة لا يستطيع الموقع نفسه التنبيه عنها.

## 12) نسيان كلمة مرور لوحة التحكم
- من صفحة الدخول → «نسيت كلمة المرور؟» يصل رابط صالح 30 دقيقة لمرة واحدة (يتطلب إعداد البريد). يسجّل الخروج من كل الأجهزة بعد التغيير.
- بديل دائم من جهازك أو من Vercel CLI: `npm run admin:create -- your@email.com "الاسم" owner` مع `DATABASE_URL` للإنتاج — يعيد تعيين كلمة المرور ويطبعها مرة واحدة.

## 13) سياسة أمان المحتوى (CSP)
مضبوطة في `next.config.ts`: تسمح فقط بسكربتات المتجر وأدوات القياس المدعومة (Google / Meta / TikTok) وصور Supabase. إن أضفت خدمة خارجية جديدة تحمّل سكربتًا أو صورًا فأضف نطاقها هناك وإلا سيحظرها المتصفح.

## 14) الرسائل النصية للعملاء (تقنيات) — اختياري ومدفوع
1. افتح حسابًا في https://taqnyat.sa وسجّل **اسم مرسل** (Sender Name) واعتمده (يتطلب السجل التجاري).
2. من لوحة تقنيات أنشئ مفتاح API (Bearer Token).
3. متغيرات البيئة: `TAQNYAT_API_KEY=...` و `SMS_SENDER=اسم المرسل المعتمد`.
4. لوحة التحكم → الإعدادات → الإشعارات: فعّل «رسالة SMS للعميل». تُرسل رسالتان فقط: تأكيد الطلب، والشحن مع رقم التتبع. كل رسالة تظهر في صفحة الطلب بحالتها.
5. التكامل مكتوب على التوثيق الرسمي (`POST https://api.taqnyat.sa/v1/messages`) ولم يُجرَّب على حساب حقيقي: أرسل طلبًا تجريبيًا لرقمك قبل الاعتماد عليه.

## 15) التحقق بخطوتين للوحة التحكم
لوحة التحكم → «حسابي والأمان» → إعداد التحقق بخطوتين، ثم امسح الرمز بتطبيق مصادقة (Google Authenticator أو Microsoft Authenticator). احفظ رموز الاسترداد العشرة في مكان آمن. إن فقد موظف جواله ورموزه يستطيع المالك إلغاء التحقق بخطوتين له من صفحة المستخدمين. فعّله لكل الحسابات قبل الإطلاق.

## 16) حسابات العملاء
- الدخول برمز من 6 أرقام يصل للجوال (يتطلب تقنيات) أو للبريد (يتطلب Resend). بدون أي منهما في الإنتاج لن يستطيع العملاء تسجيل الدخول — الشراء كضيف يبقى متاحًا دائمًا.
- محليًا (بدون مزود رسائل) يظهر الرمز على الشاشة وفي نافذة الخادم للتجربة فقط.
- إثبات رقم الجوال يربط تلقائيًا الطلبات السابقة التي تمت كضيف بنفس الرقم.
- العميل يستطيع حذف حسابه بنفسه (تبقى سجلات الطلبات لأغراض محاسبية دون ربطها بالحساب).


## 17) تابي وتمارا (اشترِ الآن وادفع لاحقًا) — اختياري
يتطلب كل منهما حساب تاجر معتمدًا لديهم (سجل تجاري وتوقيع اتفاقية). لا يظهر أي منهما في صفحة الدفع إلا بعد وضع مفاتيحه **وتفعيله** من لوحة التحكم → الإعدادات → طرق الدفع.

**تابي**
1. من لوحة تاجر تابي خذ المفتاح السري (`sk_test_...` للتجربة) ورمز التاجر (merchant code) وضعهما في `TABBY_SECRET_KEY` و`TABBY_MERCHANT_CODE`.
2. سجّل Webhook على `https://your-domain.sa/api/payments/tabby/webhook` مع ترويسة `X-Webhook-Secret` بقيمة عشوائية طويلة، وضع نفس القيمة في `TABBY_WEBHOOK_SECRET`.
3. للتجربة في بيئة الاختبار: جوال `+966500000001` ورمز التحقق `8888` (حسب توثيق تابي — تأكد منه قبل الاختبار). رقم الرفض التجريبي في توثيقهم يفيد لتجربة حالة الرفض.
4. المتجر يتحقق من حالة الدفعة من واجهة تابي نفسها (لا يعتمد على محتوى الـWebhook)، ثم «يلتقط» المبلغ تلقائيًا بعد الموافقة.

**تمارا**
1. خذ API Token من لوحة تمارا وضعه في `TAMARA_API_TOKEN`. أثناء التجربة ضع `TAMARA_API_BASE=https://api-sandbox.tamara.co` واحذفه عند الانتقال للحي.
2. سجّل Webhook (Notification URL) على `https://your-domain.sa/api/payments/tamara/webhook` لأحداث الموافقة والإلغاء.
3. عند موافقة تمارا يعتمد المتجر الطلب (authorise) ويعتبره مدفوعًا، ويتم «الالتقاط» تلقائيًا عند تحويل الطلب إلى «تم الشحن» مع اسم شركة الشحن ورقم التتبع. لا تترك الطلبات المدفوعة دون شحن طويلًا (تمارا تلتقط تلقائيًا بعد مدة محددة في اتفاقيتك).

**مهم:** الربط مكتوب على التوثيق الرسمي للطرفين ومغطّى باختبارات تحاكي ردودهم، لكنه **لم يُجرَّب على حساب حقيقي**. نفّذ قبل الإطلاق: طلب موافَق عليه، طلب مرفوض (يجب أن يُلغى الطلب ويرجع المخزون ويظهر للعميل أن يختار طريقة أخرى)، شحن طلب تمارا، واسترجاع من لوحة التحكم. لا تكتب في المتجر أي عبارات تسويقية عن «بدون فوائد» أو عدد الدفعات إلا بما تسمح به اتفاقيتك معهم.
